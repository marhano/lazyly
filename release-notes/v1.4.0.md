## New: Angular projects

- Register an Angular project and PublishTool builds it via `npm run build` and deploys it to
  IIS with a dedicated "No Managed Code" app pool -- no more manually configuring the pool
  yourself.
- If your build output doesn't already have one, PublishTool writes a default `web.config` with
  a URL Rewrite rule so client-side routes (e.g. hitting `/dashboard` directly) don't 404.
- Correctly handles Angular 17+'s newer builder, which nests the real site under a `browser`
  subfolder.

## New: Android projects (Capacitor/Cordova)

- Register a hybrid Capacitor or Cordova project and build an APK or AAB straight from
  PublishTool.
- Release signing via a keystore dialog modeled on Android Studio's own "Generate Signed
  Bundle/APK" screen -- your keystore password never leaves this machine.
- A new "Android Config" section on the Publish tab finds and edits Bundle Id, Display Name,
  Version Number, and Build Number before building.

## New: App Config editing

- Edit Web.config/App.config appSettings, appsettings.json, or an Angular/Ionic
  `environment.ts` file right from the Publish tab.
- If no fixed config path is set, PublishTool looks for the right file automatically.

## New: Audit trails

- The Projects tab now has a "History" button (per project) and an "All history" button --
  every add, remove, settings change, publish, deploy, and build action is logged with who did
  it and when.
- The IIS tab gets the same treatment for site/application pool start, stop, remove, and recycle
  actions.
- A new "Audit Logs" tab combines Projects, Firewall, and IIS history into a single searchable
  view.

## IIS tab

- Site and application pool actions are now compact, icon-only buttons that show or hide based
  on the site's current state (e.g. Start disappears once it's running).
- Added a "Remove site" action -- also removes its dedicated application pool, if it has one.
- Added "Manual Deploy": create a brand-new IIS site or deploy into an existing one from a
  folder or zip file, without needing a registered project. Works against your own machine or
  the dev server.

## Projects

- Project Settings is now split into Local (your own machine's paths, your own IIS setup) and
  Shared (team-wide) sections, so a non-developer can safely edit a project without touching
  anything that doesn't apply to them.
- The Dependencies tab (Help) now also checks for Node.js/npm, Java, and the Android SDK.

## Other

- PublishTool no longer requires Administrator just to open -- you'll only be asked to elevate
  when you actually try to manage this machine's own IIS or firewall rules.
- Opening PublishTool while it's already running now brings the existing window to the front
  instead of launching a second copy.

## Fixes

- Git branch loading now works for Android/Angular projects (it only ever worked for .NET
  projects before).
- Fixed the `environment.ts` editor failing to parse some real-world files.
- Fixed a project's type sometimes reverting to ".NET" after being saved while using the dev
  server.
- Fixed a couple of startup crashes and some IIS-tab buttons rendering blank.
