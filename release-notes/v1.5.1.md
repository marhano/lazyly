## New: Run tests as part of a publish

- The Publish tab now has "Run unit tests" / "Run E2E tests" toggles right alongside the publish
  itself, for projects with those suites configured -- no separate step needed afterward. E2E can
  target a one-off URL for just this publish, or fall back to its configured environment.

## New: Publish profile picker on the Publish tab

- .NET projects now pick their MSBuild **Publish profile** on the Publish tab itself, from a select
  listing every `.pubxml` file actually found under the project's `Properties\PublishProfiles`
  folder -- nothing to type (or mistype) in the project's Edit dialog anymore.

## New: Redesigned Tests dialog, run suites independently

- The Projects tab's build history now opens a dedicated **Tests** dialog instead of a single
  combined "Run Tests" button -- Unit Test and E2E (whichever are configured) each get their own
  row, their own status, and their own Run button.
- Running E2E prompts for which dev-server environment to target every time, instead of always
  using the project's configured default.
- Running one suite type no longer overwrites the other suite's last-known result for the same
  build -- each keeps its own result and timestamp until it's re-run.

## Other

- Remote (dev-server) test execution for classic .NET Framework test projects no longer needs
  Visual Studio/Build Tools installed on the server -- the required test platform now ships bundled
  with PublishTool.Hosting itself. **Requires redeploying PublishTool.Hosting** to take effect.
- CLI: `add-project --pubxml` is now optional; `publish` gained `--pubxml-name` to pick the profile
  for that one publish, matching the new GUI behavior.
