## New: Dev Server Relays (Settings)

- Save a colleague's already-connected machine as a bookmarked relay, and switch the active
  Remote Build Hosting URL to it with one click ("Use" tests the connection immediately too).
- "Host a Relay" lets this machine act as the relay: pick a listen port and the dev server's
  address, and PublishTool sets up the `netsh` port forward and firewall rule for you -- one
  Administrator confirmation, no manual command prompt. Stop it just as easily.
- "Relay All IIS Sites" relays every port the dev server's IIS sites use in a single click (and a
  single elevation prompt, no matter how many ports), so a colleague can reach any of them through
  this machine. "Stop All IIS Site Relays" tears them all down the same way.

## Settings tab reorganized

- Replaced the long single scrolling page with a sidebar: General, Projects, Remote Build
  Hosting, and Dev Server Relays each get their own screen.

## IIS tab

- Application pools get a new "Set identity" action (ApplicationPoolIdentity, NetworkService,
  LocalService, or LocalSystem).
- Added a "Show all IIS sites" toggle -- off by default, showing only sites PublishTool has
  deployed to (tagged `[PT]`); switch it on to see every site on the server.

## Projects

- New dev-server environments now default their host root path to
  `E:\ProgramData\PublishTool\PublishBuilds`.
- At least one dev-server environment is now required to save a project (Android projects are
  exempt, since there's nothing to deploy an APK/AAB to).
- Dev-server environment settings are always visible now, regardless of the Remote IIS toggle --
  that toggle only controls whether they're offered as a Publish tab deploy target.
- The Remote IIS toggle (and its environments section) is hidden entirely for Android projects,
  same as Local IIS already was.

## Fixes

- All timestamps across the app (build history, audit trails, IIS/deployment dates, Event Logs,
  the Build Archive web pages) were showing raw UTC time instead of Philippine time -- now
  corrected everywhere, in 12-hour format. No data was ever stored wrong; this was a display-only
  fix, so existing history now just displays correctly.
