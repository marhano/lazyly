## Fix: the selected publish profile's build configuration is now actually used

- MSBuild publishes always built with the `Release` configuration, no matter which publish
  profile was selected -- for most projects that's the only configuration a profile ever pointed
  at, so this was invisible. For a project with brand/environment-specific MSBuild configurations
  (e.g. a `.pubxml` whose own `LastUsedBuildConfiguration` is `Release-MyBrand`, wired up to its own
  `DefineConstants` and/or a `Web.Release-MyBrand.config` transform), the profile you picked never
  actually changed what got built.
- PublishTool now reads each profile's own build configuration and passes it to MSBuild instead of
  hardcoding `Release` -- matching what Visual Studio itself does when you publish with that profile
  selected there. The Publish tab's output log now also prints which profile and configuration are
  being used for that build, so it's visible rather than assumed.
